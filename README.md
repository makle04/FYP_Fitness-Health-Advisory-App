# FitSense AI
### Clustering and Personalised Multiple Advisory System for Fitness and Healthy Lifestyle

> A full-stack machine learning application that identifies your fitness archetype through unsupervised clustering and delivers personalised workout and dietary recommendations in real time.

---

## Overview

FitSense AI applies **UMAP + HDBSCAN** density-based clustering to gym member fitness profiles, discovers 14 distinct fitness archetypes without any predefined labels, and serves real-time predictions through a **Flask REST API** consumed by a **React web frontend**. A dietary advisory module computes personalised caloric and macronutrient targets using the Mifflin-St Jeor formula.

| Component | Technology |
|-----------|-----------|
| ML Pipeline | Python 3.10, pandas, scikit-learn, umap-learn, hdbscan |
| API | Flask, Flask-CORS, joblib |
| Frontend | React 18, React Router v6 |
| Visualisation | matplotlib, seaborn |

## How to Run

> **Important:** Steps must be completed in order. The API and frontend both depend on files generated by `main.py`.

### Step 1 — Train the model

Run the full offline ML pipeline from the project root:

```bash
python project/main.py
```

Expected terminal output:

```
INFO: Loading dataset
INFO: Pruned 270 unrealistic records
INFO: Dropped 0 rows during feature engineering
INFO: Searching best UMAP + HDBSCAN configuration
INFO: Selected parameters: UMAP neighbors=30, HDBSCAN min_cluster_size=25
INFO: Cluster summary: {'clusters': 14, 'noise_ratio': 0.16}
INFO: Saved results to project/data/output_with_activity_levels.csv
INFO: Training cluster prediction model
INFO: Cluster prediction model saved
```

This generates two files:
- `project/data/output_with_activity_levels.csv` — labelled dataset with cluster assignments and recommendations
- `project/models/cluster_model.pkl` — serialised Random Forest classifier

---

### Step 2 — Start the Flask API

```bash
python project/api.py
```

API runs at `http://localhost:5000`

Verify it is running by visiting `http://localhost:5000` — you should see:

```
Fitness Health Advisory API Running
```

---

### Step 3 — Start the React frontend

Open a **separate terminal**:

```bash
cd fitness-frontend
npm start
```

Frontend opens automatically at `http://localhost:3000`

> Both the API (port 5000) and the frontend (port 3000) must be running simultaneously for the system to work end to end.

## API Reference

### `POST /predict`

Accepts nine user input attributes and returns a cluster assignment and personalised recommendation.

**Request**

```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "Age": 28,
    "Weight_kg": 70,
    "Height_m": 1.75,
    "Session_Duration_hours": 1.5,
    "Calories_Burned": 600,
    "Max_BPM": 185,
    "Resting_BPM": 60,
    "Avg_BPM": 140,
    "Water_Intake_liters": 2.0
  }'
```

**Response**

```json
{
  "cluster": 1,
  "recommendation": "High-intensity interval training with explosive movements and adequate recovery."
}
```

**Input fields:**

| Field | Type | Description |
|-------|------|-------------|
| `Age` | float | Age in years |
| `Weight_kg` | float | Body weight in kilograms |
| `Height_m` | float | Height in metres |
| `Session_Duration_hours` | float | Workout duration (0.3 – 3.0 hours) |
| `Calories_Burned` | float | Calories burned per session |
| `Max_BPM` | float | Maximum heart rate during session |
| `Resting_BPM` | float | Resting heart rate |
| `Avg_BPM` | float | Average heart rate during session |
| `Water_Intake_liters` | float | Water intake in litres (0.5 – 4.0) |

## Machine Learning Pipeline

```
Raw Dataset (1,800 records)
        ↓
  Preprocessing
  Column standardisation, type coercion, missing value removal
        ↓
  Physiological Pruning
  9 hard constraints + heart rate consistency rule → 1,501 records
        ↓
  Feature Engineering
  BMI, Intensity, HRR, BPM Efficiency, Hydration Ratio → 8-feature matrix
        ↓
  UMAP Dimensionality Reduction
  n_components=10, n_neighbors=30, random_state=42
        ↓
  HDBSCAN Clustering
  Grid search: n_neighbors ∈ {20,30,40} × min_cluster_size ∈ {25,30,35}
  Result: 14 clusters, noise ratio 16.0%, composite score 11.76
        ↓
  Random Forest Classifier
  n_estimators=400, max_depth=10, min_samples_split=10
  Pipeline consistency accuracy: 99.92%
        ↓
  Flask API → React Frontend
```

## Dataset

| Property | Value |
|----------|-------|
| Source | Publicly available synthetic dataset (Kaggle) |
| Raw records | 1,800 |
| Features | 15 (demographic, physiological, activity, hydration) |
| After preprocessing | 1,501 |
| After noise exclusion | 1,261 (used for classifier training) |
| Ethics approval required | No — synthetic data, no real personal health data |

**Engineered Features:**

| Feature | Formula | Physiological Meaning |
|---------|---------|----------------------|
| BMI | Weight / Height² | Standardised body composition |
| Intensity | Calories Burned / Session Duration | Average caloric expenditure rate per hour |
| HRR | Max BPM − Resting BPM | Cardiovascular capacity headroom |
| BPM Efficiency | Avg BPM / Max BPM | Proportion of maximum effort sustained |
| Hydration Ratio | Water Intake / Weight | Body mass-normalised hydration behaviour |

## Known Limitations

- Runs as **localhost only** — no cloud or production deployment configured
- The API and frontend must both be running simultaneously
- Dietary module uses **deterministic formula-based computation** — not a learned model
- Meal plan templates are **static per goal category** — not fully individualised
- Model accuracy (99.92%) reflects **pipeline consistency** against training data, not generalisation to unseen populations
- Dataset is **synthetic** — cluster structures and performance on real-world gym data may differ
